# konradfedorczyk.dev

> README generated by Qwen 3.8

Personal blog and portfolio of [Konrad Fedorczyk](https://konradfedorczyk.dev), software developer. Built with [Astro](https://astro.build) as a fully static site.

## Stack

- **Astro 7** — static output, styles inlined at build time (`inlineStylesheets: 'always'`)
- **MDX** — all content is authored in `.mdx` (`.md` also accepted)
- **Satteri** — Markdown processor, with a custom Shiki copy-code button transformer and a TOC-observing HAST plugin; code themes: `nord` (light) / `vitesse-dark` (dark)
- **SCSS** — partials (`_globals`, `_typography`, `_spacing`, `_breakpoints`) feeding a light/dark theme system built on CSS custom properties (`[data-theme="light" | "dark"]`)
- **nanostores** — theme + menu state (`src/stores/themeStore.ts`, `src/stores/menuStore.ts`), persisted to `localStorage`, seeded from `prefers-color-scheme`
- **three.js** — vanilla 3D head component in `src/components/3d/Head3D/` (no React)
- **sharp** — image optimization; **astro-favicons** — favicons generated at build time from `src/assets/head3d-preview.png`
- **Hanken Grotesk** — self-hosted Google font; **@astrojs/sitemap** — SEO sitemaps

Node `>= 22.12.0` required (see `engines` in `package.json`).

## Commands

All commands are run from the project root:

| Command | Action |
| :------ | :----- |
| `npm install` | Install dependencies |
| `npm run dev` | Start the dev server at `localhost:4321` |
| `npm run dev:host` | Start the dev server, exposed on the network (`--host`) |
| `npm run build` | Build the production site to `./dist/` |
| `npm run preview` | Preview the production build at `localhost:4322` |
| `npm run build:preview` | Build with `SITE_URL=http://localhost:4322` and serve the preview on `4322` — used for local testing of absolute URLs |
| `npm run astro ...` | Run any Astro CLI command (e.g. `npm run astro add`, `npm run astro check`) |

## Content

All three collections — `notes`, `articles`, `projects` — are defined in `src/content.config.ts` and validated against a shared Zod schema:

| Collection | Required frontmatter | Optional |
| :--------- | :------------------- | :------- |
| `notes` | `title`, `description`, `pubDate` | — |
| `articles` | `title`, `description`, `pubDate` | — |
| `projects` | `title`, `description`, `pubDate` | `finished` (boolean) |

### Example note (`src/content/notes/example.mdx`)

```mdx
---
title: TypeScript
description: A deep dive into how TypeScript has transformed front-end development workflows and why strict mode should be the default for every team adopting type checking
pubDate: 2021-03-20
---
Lorem ipsum dolor sit amet, consectetur adipiscing elit.

## Subtitle

You can write regular Markdown **and** embed MDX / React-free Astro
components right where you need them.
```

Frontmatter rules:

- `title` — string
- `description` — string
- `pubDate` — ISO date, `YYYY-MM-DD` (coerced to `Date` by the schema)

## Architecture notes

- Fully static Astro build (`output: "static"` in `astro.config.mjs`); the only environment knob is `SITE_URL` (defaults to `https://konradfedorczyk.dev`)
- Theme toggle state lives in nanostores (`themeStore.ts`); an inline script in `Layout.astro` applies the stored theme before hydration, and an effect re-applies it on every route transition
- SCSS partials are consumed via `@use` in component `<style lang="scss">` blocks; design tokens live in CSS custom properties scoped per theme
- All stylesheets are inlined at build time — no separate CSS requests in production
- The 3D head is a self-contained Astro + three.js component (no framework UI library)
